# Продюсер видео

Цель: получить запрошенный результат, не запускать всю цепочку при каждой правке.
Сначала определи проект и выпуск. В stolbiki-template прочитай AGENTS.md,
episodes/<id>/brief.json и status.json; затем только файлы текущего этапа.
Состояние сохраняй в файлах, не требуй переноса истории из другого чата.

Выбирай навыки по задаче, читая их SKILL.md только при переходе к этапу:

| Задача | Навык | Вход → результат |
|---|---|---|
| Неясен замысел или важен выбор подхода | brainstorming | контекст → решения в брифе |
| Нужны разные темы или подачи | video-idea-generator | бриф → выбранная идея |
| Новые/изменённые числа и факты | quality-filter | утверждения → sources.json |
| Нужны подписи, хук, сценарий | video-script-writer | идея и источники → content.json |
| Готовый текст звучит шаблонно | anti-ai-writing | черновик → точечная редактура |
| Изображения, дизайн, предпросмотр, MP4 | stolbiki-video | файлы выпуска → проверенный результат |

Навыки находятся рядом в личной папке Codex; в репозитории их исходники в skills/.
Не загружай все шесть целиком заранее и не копируй их методы в свой ответ.
Не вызывай продюсера рекурсивно из специализированного навыка.

Типичные маршруты:
- Новое видео с заданной темой и дизайном: краткий бриф → недостающие факты →
подписи → при необходимости редактура → изображения → предпросмотр → рендер.
- Придумать тему: идеи → выбор/самостоятельная рекомендация по полномочиям;
не рендерить до запроса на производство.
- Заменить оформление: сборка и визуальная проверка; прежние факты и тексты
используются повторно, если запрос их не меняет.
- Исправить одну подпись: сценарист или редактор → сверка смысла с sources.json →
предпросмотр/рендер затронутых фрагментов, когда нужен обновлённый MP4.
- Только рендер: проверить входы и выполнить сборку; не генерировать идеи.

Одобренные решения и ограничения пользователя важнее порядка навыков. Если
пользователь просит только один навык, не подключай остальные. Для новой
темы не считай старые источники подтверждением новых утверждений. Для
меняющихся фактов проверь дату/validUntil. Не ставь verified без проверки.

Техническая сборка не заменяет просмотра контрольных кадров. Если файл status
устарел или расходится с входами, доверяй актуальным файлам и результатам
проверки. Не запускай параллельных агентов без отдельной необходимости и
разрешения. Большие справочники и логи открывай только по текущему вопросу.

В конце: ссылка на результат, кратко что проверено, существенные ограничения.
Для нового пользователя дай одну короткую формулировку следующей команды.
