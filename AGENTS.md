# Работа с проектом

Общий движок карточек сохраняется; выпуски меняют данные, дизайн, мир и медиа.
Не читай весь репозиторий для обычного выпуска.

- Вход: `episodes/<id>/brief.json` и `status.json`.
- Текст/факты: `content.json`, `sources.json` только этого выпуска.
- Рисунки: `assets.json`, `assets/catalog.json`, затем отдельная нужная сцена.
- Дизайн: `designs/catalog.json`; фон мира: `worlds/catalog.json`.
- Движение: `src/engine/`; общая раскладка: `src/Video.tsx`, `src/Card.tsx`.
- Контракты: `docs/contracts.md`. Пользование и примеры: `docs/usage.md`.
- Навыки: короткие входы в `skills/`; справочники читать по задаче.
- Для полного видео использовать `video-producer`; при точечной правке только
  нужный этап. Явное «только один навык» соблюдать.

Команды из корня:
`npm run episode -- list`
`npm run episode -- new <id> --title "Тема" --seconds 60`
`npm run episode -- validate <id>`
`npm run episode -- preview <id>`
`npm run episode -- render <id>`
`npm test` и после prepare: `npm run typecheck`.

Новый выпуск не редактирует старый. src/generated, public/generated, build и out
создаются командами; их не редактировать и не коммитить. Кэш не удалять при правках.
Полный рендер выполняется после просмотра out/<id>/check.jpg. Обновлённые числа
и факты требуют сверки источников. Дата проверки не доказывает истинность сама.
Для визуальных изменений проверить оба семейства оформления; для времени/кэша
запустить tests. Не создавать тесты на формулировки документации.
Большие логи открывать только при ошибках. Результаты: out/<id>/video.mp4,
thumb.png, verification.json. Рабочие файлы выпуска и важные решения хранить в Git.
